# ADR 0003：Exception to C-NET-02：用户可选的全局 ping 阻断

- 状态：已批准（维护者 2026-11-04 在讨论 ICMP 处理方式时选择方案 B）
- 日期：2026-11-04
- 涉及约束：C-NET-02（例外）、C-NET-05、C-NET-06、C-NET-07、C-UI-01

## 背景

拦截层只改道 TCP 与 UDP，目标进程的 ICMP 会直接发出，目标地址能看到真实 IP。沙盒实测（2026-11-04）：

| 发送方式 | `ALE_AUTH_CONNECT` 上的进程 |
| --- | --- |
| `ping.exe`、.NET `Ping` 等系统 ping 接口（`IcmpSendEcho`） | System（PID 4），不是调用的进程 |
| 进程自己开的原始 ICMP 套接字 | 进程自己 |

第二种可以只挡目标进程，不需要例外（见下面「不属于这个例外的部分」）。第一种分不出是哪个进程发的，只有两个选择：放行所有进程的，或者挡住所有进程的。后者违反 C-NET-02「非目标进程的数据包禁止被改写、延迟」，也违背项目的承诺「其余流量完全不受影响」。

有的用户宁愿这台电脑 ping 不通，也不想让目标进程的 ping 漏出去。

## 决定

新增方案字段 `icmp.block_all_ping`（schema 3）。打开后，**会话期间**用动态 WFP 过滤器挡住本机**所有进程**发往外部的 ICMP 回显请求。

## 影响范围

只包含下面这些：

- **协议：** 只挡回显请求（ICMP 类型 8、ICMPv6 类型 128）。IPv6 邻居发现这类协议运转需要的 ICMPv6 不受影响，挡掉它们 IPv6 就断了。
- **地址：** 回环、链路本地、组播与广播放行（C-NET-05）。局域网地址属于「外部」，同样被挡。
- **时间：** 只在会话期间。过滤器属于动态 WFP 会话，会话结束或服务退出（含崩溃）时由系统删除（C-NET-06）。`allow` 策略下内核放弃重启、会话结束时一并撤销。
- **用户可感知的后果：** 这台电脑上所有程序在会话期间都 ping 不通外部地址，用 ping 测延迟的游戏或软件可能显示超时。

## 怎么控制住这个例外

- **默认关闭。** 新方案和从旧版本迁移来的方案都是关闭的，行为不变。
- **开启前要确认。** 界面上打开开关时弹出确认对话框，说明会影响所有程序（与接管系统 DNS 相同，C-NET-09）；关闭不用确认。
- **装不上就不启动会话。** 用户要求的保护不能悄悄失效（`session.fail_closed_unsupported`）。
- **有端到端测试。** `leak_e2e` 确认开关打开时回显请求发不出去、回环照常、目标进程的 TCP 与 UDP 不受影响，会话结束和服务被杀之后 ping 都恢复；开关关闭时非目标进程的 ping 不受影响。

## 不属于这个例外的部分

目标进程 TCP、UDP 以外的协议（原始套接字发的 ICMP 等）在精确模式 + `fail_policy = block` 时按可执行文件挡住。这是 C-NET-07 本来的要求，只影响目标可执行文件，不需要例外。

## 考虑过的替代方案

- **维持现状，只记为已知限制：** 不违反 C-NET-02，但想彻底不漏的用户没有办法。
- **挡住全部 ICMP：** IPv6 会断网。
- **只要有会话就无条件挡 ping：** 所有用户都承担后果，默认就违背「其余流量完全不受影响」。
- **挡住目标进程的系统 ping 接口调用：** 需要注入或内核驱动，不值得，也超出 `design` 第 1.2 节的范围。

## 失效条件

出现下面任一情况时重新评估，例外可能不再需要：

- Windows 或 WFP 能把 `IcmpSendEcho` 发的包归属到调用进程；
- 决定用自己的驱动处理 ICMP（需要新的决定，AGENTS 第 8 节第 2 条）。
