# ADR 0002：发版用一次性证书，服务按「同一张证书」校验客户端

- 状态：已采纳（维护者 2026-11-04 确认，AGENTS 第 8 节第 1、4 条）
- 日期：2026-11-04
- 涉及约束：C-SEC-02、C-SEC-08、C-DEP-04、C-DEP-05、C-DRV-01

## 背景

GitHub Release 需要带能在任何机器上使用的客户端。T-110 的做法只适用于开发机：签名证书是本机自签名证书，私钥
不可导出；服务用 `WinVerifyTrust` 校验，要求证书链接到受信任的根，再比较主题。其他机器上的用户必须先以管理员身份
把这张证书加入「受信任的根」，否则服务拒绝所有界面。

`docs/design.md` 9.3 假定用公共信任的证书做 Authenticode 签名。这需要账号、身份核验和费用，目前没有。

## 决定

1. **每次打包新建一次性自签名证书**（`cargo xtask bundle`）：私钥不可导出，打包结束后连同私钥删除。本机打包与
   GitHub Actions 走同一条路径。发版不需要任何 CI 密钥，也没有可以被窃取、被所有用户信任的长期私钥。
2. **服务比对证书本身**（`platform-win::authenticode`、`svc::client_auth`）：客户端必须在安装目录内，签名未被改动、
   证书在有效期内，且签名证书的 SHA-256 与服务自己的相同。`WinVerifyTrust` 的结果中只放宽 `CERT_E_UNTRUSTEDROOT`
   一种；文件被改动、证书过期、证书被明确禁用等任何其他结果都拒绝。服务自身没有有效签名时仍拒绝所有客户端。
3. **发布者身份由 GitHub 的构建证明回答**：一次性证书不能说明安装器出自谁手，所以发版时同时发布 `SHA256SUMS.txt`
   与 `actions/attest-build-provenance` 的证明，用户可用 `gh attestation verify` 核对。
4. **版本号跟随 tag**：发版工作流在构建前运行 `cargo xtask set-version <tag>`。

## 为什么仍然满足 C-SEC-02

C-SEC-02 要求客户端「可执行文件位于安装目录，且 Authenticode 签名主体与服务一致」。证书相同则主体必然相同，这是
比比较主题更严格的条件：自签名证书的主题任何人都能照抄，但私钥已经删除，没有人能再用这张证书签名。

不再需要证书链受信任。这道校验要回答的是「这个客户端是否与服务出自同一次安装」，而不是「机器管理员是否信任某个
发布者」。参照物是服务自己的可执行文件，能替换它的人已经拥有管理员权限，校验本来就挡不住。安装目录的写权限仍然是
这道校验的前提，与之前相同。

## 代价

- Windows 会提示「未知发布者」，SmartScreen 可能拦截下载的安装器。自签名方案都消除不了，只有公共信任的证书能逐步改善。
- 签名没有时间戳，证书过期后签名失效，服务会拒绝界面（fail-closed）。证书有效期定为 20 年；私钥已删除，长有效期
  没有额外风险。
- 每个版本的证书都不同。升级时服务与界面由同一个安装器替换，不会出现长期不一致；升级中途失败时服务拒绝界面，
  重新安装即可恢复。

## 没有采纳的方案

- **固定的自签名证书，私钥放 GitHub Secrets**：每个用户都要以管理员身份信任根证书；私钥一旦泄漏，所有信任过它的
  机器都受影响。
- **只在开发机上打包并上传**：私钥不离开本机，但发版不是自动的，用户同样要信任根证书。
- **公共信任的代码签名**（Azure Artifact Signing、SignPath、OV 证书）：用户体验最好，但要先办账号和身份核验。
  以后可以切换：只需替换 `xtask/src/bundle.rs` 的证书来源与 `xtask/bundle/sign.ps1`，服务的校验不用改（证书受信任时
  `WinVerifyTrust` 直接成功，比对同样成立）。

## 影响

- 取消 `trust-signing-cert.ps1` 与导出的 `.cer`，安装前不需要任何证书步骤。开发机证书库里旧的
  `CN=ProcRoute Local Code Signing` 不再使用，由用户决定是否删除。
- `cargo xtask sandbox-install` 在不信任任何证书的沙盒里验证，并确认安装目录内主题相同、证书不同的界面被拒绝。
- 测试夹具在 `tests/fixtures/authenticode`（含生成脚本），证明真实的 `WinVerifyTrust` 行为。
